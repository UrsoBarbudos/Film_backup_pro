# Dублёр

**Версия:** 1.21.1

## Описание

macOS-приложение для надёжного копирования данных с внешних носителей
(флешек, карт памяти и отдельных папок) в выбранную папку назначения с
проверкой целостности файлов.

## Основные возможности

- **Единый сценарий копирования** непосредственно в выбранную папку назначения
- **Сохранение исходной структуры** внутри отдельной подпапки каждого источника
- **Интеллектуальная дедупликация файлов** — автоматическое обнаружение дубликатов по MD5 хешу
- **Хранение хешей файлов** — кэширование хешей для ускорения проверки целостности
- **Проверка целостности файлов** (MD5) с возможностью повторной проверки при ошибках
- **Два режима проверки** — полная проверка (MD5) и быстрая проверка (размер файла)
- **Возобновление незавершенного процесса** — автоматическое обнаружение и возможность продолжить прерванное копирование
- **Контрольные точки** — сохранение прогресса для безопасного возобновления
- **Оптимизированное копирование** — автоматический выбор метода копирования (shutil для малых файлов, блочное копирование для больших)
- **Drag and Drop** для источников и папки назначения
- **Поддержка отдельных файлов** в качестве источников (не только папок)
- **Создание MD логов сессий** с полной статистикой копирования
- **Темы оформления** (светлая/темная)
- **Окно прогресса** с функциями паузы и отмены
- **Предотвращение сна системы** во время копирования
- **Telegram уведомления** — отправка MD логов сессий в Telegram после завершения копирования (требует настройки Bot Token и Chat ID)
- **Настройка системных уведомлений macOS** — возможность включать/выключать уведомления через Notification Center
- **Отметка исходных носителей** — история подтверждённых резервных копий и явное предупреждение перед повторным добавлением карты
- **Автоматическая очистка старых хешей** — настраиваемая очистка хешей старше указанного количества дней
- **Графический интерфейс** на PySide6 (Qt)
- **Только для macOS** - кроссплатформенность не поддерживается

## Требования

### Для разработчиков (сборка приложения из исходников)

- **Python 3.11 или 3.12** с официального сайта python.org
- **macOS** 12.0 или новее
- **Важно:** Использование системного Python из Xcode или Python через Homebrew не рекомендуется. Это требование актуально только для разработчиков, которые собирают приложение из исходников через PyInstaller.

### Для конечных пользователей (использование готового приложения)

- **macOS** 12.0 или новее
- **Python не требуется** — приложение собирается через PyInstaller и включает все необходимые зависимости. Готовый `.app` файл можно запускать без установки Python или каких-либо дополнительных зависимостей.

## Зависимости

Проект использует следующие зависимости (см. `requirements.txt`):

- **PySide6** — GUI фреймворк на основе Qt для создания графического интерфейса
- **psutil** — библиотека для работы с системными процессами (предотвращение сна)
- **requests** — библиотека для HTTP запросов (используется для отправки уведомлений в Telegram)
- **pyinstaller** — инструмент для сборки приложения в исполняемый файл

## Старт

1. Убедитесь, что вы используете Python 3.11 или 3.12 с официального сайта python.org
2. Создайте виртуальное окружение (если еще не создано):
   ```bash
   python3 -m venv .venv
   ```
3. Активируйте виртуальное окружение:
   ```bash
   source .venv/bin/activate
   ```
4. Установите зависимости:
   ```bash
   .venv/bin/pip install -r requirements.txt
   ```
5. Запустите приложение (рекомендуемый способ — один скрипт для всех случаев):
   ```bash
   ./run.sh
   ```
   Скрипт сам подхватит `.venv`, если он есть, иначе запустит через `python3`. Если виртуальное окружение уже активировано:
   ```bash
   .venv/bin/python app.py
   ```
   или
   ```bash
   python3 app.py
   ```
   Альтернатива с логированием в файл:
   ```bash
   ./run_in_venv.sh
   ```

**Важно:** На macOS часто доступна только команда `python3`, а не `python`. Используйте `./run.sh`, `python3 app.py` или `.venv/bin/python app.py`.

### Если приложение не запускается

- **«command not found: python»** — запускайте через `./run.sh` или `python3 app.py`.
- **Окно не открывается** — проверьте, что установлен PySide6: `python3 -c "import PySide6"`.
- **Ошибки импорта** — создайте venv и установите зависимости: `python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`, затем `./run.sh`.

## Структура исходников

### Основные модули

- `app.py` — главное окно приложения (GUI на PySide6), координация UI компонентов
- `engine.py` — точка входа для запуска процесса резервного копирования
- `settings_window.py` — окно настроек приложения
- `progress_window.py` — окно прогресса копирования (только UI и анимации)
- `config.py` — управление настройками приложения
- `themes.py` — управление темами оформления (светлая/темная)
- `utils.py` — вспомогательные функции
- `sleep_prevention.py` — предотвращение сна системы во время копирования
- `checkpoint_manager.py` — управление контрольными точками для возобновления процесса
- `notifications.py` — отправка уведомлений о завершении копирования (поддерживает Telegram Bot и системные уведомления macOS)
- `debug_logger.py` — `DebugLogger` — отладочное логирование для разработки

### Менеджеры состояния и контроллеры

- `backup_state_manager.py` — `BackupStateManager` — управление состоянием процесса копирования
- `source_manager.py` — `SourceManager` — управление списком источников
- `backup_resume_handler.py` — `BackupResumeHandler` — логика возобновления незавершенного процесса
- `backup_launcher.py` — `BackupStarter` — запуск процессов резервного копирования
- `backup_process_controller.py` — `BackupProcessController` — координация процессов копирования
- `progress_view_model.py` — `ProgressViewModel` — управление состоянием прогресса (ViewModel паттерн)
- `verification_dialog_handler.py` — `VerificationDialogHandler` — обработка диалогов проверки целостности

### Компоненты резервного копирования (`backup_components/`)

- `backup_orchestrator.py` — `BackupOrchestrator` — главный координатор процесса копирования
- `file_copier.py` — `FileCopier` — копирование файлов с прогрессом
- `file_verifier.py` — `FileVerifier` — проверка целостности файлов (MD5 или размер)
- `backup_notifier.py` — `BackupNotifier` — отправка уведомлений о статусе процесса
- `backup_logger.py` — `BackupLogger` — создание MD логов сессий
- `backup_stages.py` — определение этапов процесса копирования (Strategy Pattern)
- `copy_strategy.py` — `CopyStrategy` — выбор метода копирования в зависимости от размера файла

### Архитектурные компоненты

- `interfaces.py` — интерфейсы (Protocol) для Dependency Injection:
  - `IConfig` — интерфейс конфигурации
  - `ICheckpointManager` — интерфейс управления контрольными точками
  - `IFileSystemInterface` — интерфейс работы с файловой системой
  - `IFileCopier` — интерфейс для копирования файлов
  - `IFileVerifier` — интерфейс для проверки целостности файлов
  - `IDebugLogger` — интерфейс для отладочного логирования
- `repositories/` — репозитории для работы с файловой системой:
  - `file_system_repository.py` — `FileSystemRepository` — реализация работы с файловой системой

### UI компоненты

#### Виджеты (`widgets/`)

Назначение: проверка инвариантов DI и контрактов API; скрипты вызываются вручную или из `smoke_all.py`. Это **контрактные проверки для рефакторинга**, не бизнес-функция приложения; **скрипты не удалять.**

- `contract_no_get_current_context_usage.py` — контракт использования `get_current_context()`
- `contract_phase4_finalization.py` — контракт финализации DI (фаза 4)
- `contract_start_backup_process.py` — контракт API запуска бэкапа
- `di_readiness_check.py` — проверка готовности DI (отсутствие импортов из `factories`)
- `di_smoke.py` — smoke-проверка DI/composition
- `smoke_all.py` — единая точка запуска набора контрактных и smoke-проверок

### Конфигурация и сборка

- `requirements.txt` — зависимости проекта

## Архитектура проекта

Проект следует принципам **SOLID** и **KISS**:

- **Single Responsibility Principle (SRP)**: Каждый класс имеет одну четкую ответственность
- **Dependency Inversion Principle (DIP)**: Зависимости инвертированы через интерфейсы и фабрики
- **Keep It Simple, Stupid (KISS)**: Код упрощен, дублирование устранено, условия упрощены

### Основные паттерны

- **Dependency Injection**: Зависимости передаются через конструкторы
- **Factory Pattern**: Фабрики для создания зависимостей
- **Repository Pattern**: Абстракция работы с файловой системой
- **ViewModel Pattern**: Разделение логики состояния и UI
- **Strategy Pattern**: Различные этапы процесса копирования и методы копирования файлов
- **Observer Pattern**: Сигналы Qt для обновления UI из фоновых потоков

## Сборка приложения

Для сборки приложения используйте скрипт `./build.sh`. Он автоматически соберёт universal2 приложение (работает на Intel и Apple Silicon) и упакует его в простой DMG для пользователя. Результат: `dist/Dubler_VERSION_YYYY-MM-DD.dmg` — готовый к распространению образ диска. На целевом Mac: открыть DMG → перетащить `Dублёр.app` в `Программы` с выбором `Заменить` → запускать из `Программы`.
