# Тестирование приложения Dублёр на виртуальной машине

Тестирование на виртуальной машине (ВМ) имитирует «другой компьютер» и помогает проверить, что сборка запускается на чистой системе без зависимостей от вашей рабочей среды.

## Зачем тестировать на ВМ

- **Чистая среда** — другая версия macOS, другой пользователь, нет ваших настроек и путей.
- **Проверка портативности** — приложение не должно зависеть от путей и настроек машины разработчика.
- **Проверка Gatekeeper** — первый запуск и сообщение «разработчик не проверен» ведут себя как у конечного пользователя.
- **Разные архитектуры** — на отдельной ВМ можно проверить сборку под Intel (x86_64) или Apple Silicon (arm64), если хост позволяет.

## Варианты виртуальных машин на macOS

| Инструмент        | Плюсы                          | Минусы                          |
|-------------------|---------------------------------|----------------------------------|
| **UTM**           | Бесплатный, открытый, Apple Silicon и Intel | Гостевой macOS требует лицензии Apple |
| **VMware Fusion** | Зрелый продукт, хорошая поддержка гостей | Платный (есть бесплатный для личного использования) |
| **Parallels**    | Удобная интеграция с macOS      | Платный                         |

Для тестирования **macOS-приложения** нужна гостевая ОС **macOS**: лицензия Apple разрешает запуск двух копий macOS на одном компьютере (в т.ч. одна в ВМ). UTM и VMware поддерживают установку macOS в гостевую ВМ.

## Типовой сценарий тестирования

1. **Собрать приложение** на хосте:
   ```bash
   ./build.sh
   ```
   Или создать DMG:
   ```bash
   ./create_dmg.sh --build
   ```
   Вывести чеклист (пути и команду для гостевой macOS):
   ```bash
   ./run_vm_test_checklist.sh
   ```

2. **Перенести в ВМ** один из вариантов:
   - Папку `dist/Dублёр.app` (скопировать в общую папку / через сеть / образ диска), или
   - Файл `dist/Dubler.dmg` — в ВМ смонтировать DMG и перетащить приложение в «Программы» (как пользователь).

3. **В гостевой macOS** запустить приложение:
   - Двойной клик по `Dублёр.app`, или
   - В терминале: `open "/путь/к/Dублёр.app"`  
   Не запускать напрямую `Contents/MacOS/Dублёр` — на macOS 26 это может вызвать падение (SIGABRT).

4. **При первом запуске** при необходимости:
   - Правый клик по Dублёр.app → «Открыть», либо Системные настройки → Безопасность и конфиденциальность → «Всё равно открыть» для Dублёр.

5. **Проверить** открытие окна, настройки, запуск бэкапа (по возможности без реальных данных).

## Архитектура процессора

- **По умолчанию** сборка — под одну архитектуру (текущий Mac): на Apple Silicon — arm64, на Intel — x86_64. На другом типе Mac при запуске может появиться «не поддерживается этим компьютером Mac».
- **Опционально:** можно собрать **universal2** (один .app для Intel и Apple Silicon). Для этого нужен Python с [python.org](https://www.python.org/downloads/) (не Homebrew — с Homebrew PyInstaller выдаёт «is not a fat binary!»). В Dублёр.spec задать `target_arch='universal2'`. Подробнее: [BUILD_INSTRUCTIONS.md](BUILD_INSTRUCTIONS.md) — раздел «Сборка universal2».
- Чтобы проверить «другой» тип Mac, можно использовать ВМ с гостевой macOS соответствующей архитектуры (если хост это позволяет).
