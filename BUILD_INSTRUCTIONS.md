# Инструкция по сборке приложения Dублёр

## Предварительные требования

1. **Python 3.11 или 3.12** с официального сайта python.org
   - ⚠️ **ВАЖНО:** Используйте Python с официального сайта
   - ❌ Не рекомендуется использовать системный Python из Xcode
   - ❌ Не рекомендуется использовать Python через Homebrew

2. **Установленные зависимости:**
   - `PySide6` (GUI фреймворк на основе Qt)
   - `psutil` (для работы с системными процессами)
   - `requests` (для отправки уведомлений в Telegram)
   - `pyinstaller` (для сборки приложения)

## Пошаговая инструкция по сборке

### Шаг 1: Переход в директорию проекта

```bash
cd /Users/egornikitin/Documents/Production/CODING/Film_backup_pro
```

### Шаг 2: Проверка версии Python

Убедитесь, что используется правильная версия Python:

```bash
python3 --version
# или
python3.12 --version
```

Должна быть версия 3.11 или 3.12.

### Шаг 3: Установка зависимостей (если необходимо)

Если зависимости еще не установлены:

```bash
python3 -m pip install -r requirements.txt
```

Или для конкретной версии Python:

```bash
python3.12 -m pip install -r requirements.txt
```

### Шаг 4: Очистка предыдущих сборок (опционально)

Если нужно полностью очистить предыдущие сборки:

```bash
rm -rf build dist
```

### Шаг 5: Запуск сборки

**По умолчанию** сборка создаётся под **текущую архитектуру** (thin: arm64 на Apple Silicon, x86_64 на Intel). В бандл включён psutil. Для одного .app на обе архитектуры см. раздел «Сборка universal2» ниже.

#### Вариант А: Использование автоматического скрипта (рекомендуется)

```bash
chmod +x build.sh
./build.sh
```

Скрипт автоматически:
- Соберёт universal2 приложение (Intel + Apple Silicon)
- Подпишет приложение кодом (ad-hoc подпись)
- Создаст простой DMG (Dублёр.app + Программы + инструкция + .command-скрипт разблокировки)
- Настроит содержимое DMG
- Покажет результат

**Результат:** `dist/Dubler_VERSION_YYYY-MM-DD.dmg` — готовый к распространению образ диска.

#### Вариант Б: Ручная сборка через PyInstaller

```bash
python3 -m PyInstaller --clean --noconfirm "Dублёр.spec"
```

### Шаг 6: Проверка результата

После успешной сборки приложение будет находиться в:

```
dist/Dублёр.app
```

Проверьте размер приложения:

```bash
du -sh "dist/Dублёр.app"
```

Ожидаемый размер: примерно 50-80 MB (из-за библиотек Qt)

### Шаг 7: Тестирование сборки

**Рекомендуется:** всегда запускать приложение через `open` или двойной клик по `.app`. Запуск исполняемого файла напрямую (`Contents/MacOS/Dублёр`) из терминала или из IDE на macOS 26 может вызвать падение (SIGABRT в HIServices, _RegisterApplication).

#### Способ 1: Запуск через Finder (рекомендуется)

```bash
open "dist/Dублёр.app"
```

Или двойной клик по `Dублёр.app` в Finder.

#### Способ 2: Запуск из терминала (только для отладки)

```bash
open "dist/Dублёр.app"
```

Логи: `~/Library/Logs/Dubler/debug.log` или Консоль (Console.app). Не запускайте `dist/Dублёр.app/Contents/MacOS/Dублёр` напрямую — на macOS 26 это может привести к крэшу.

## Устранение проблем

### Проблема: "PySide6 не найден"

**Решение:**
```bash

```

### Проблема: "PyInstaller не найден"

**Решение:**
```bash
python3 -m pip install pyinstaller
```

### Проблема: Ошибки при сборке связанные с Qt/PySide6

**Решение:**
- Убедитесь, что используете Python с официального сайта python.org
- Не используйте Python из Homebrew или системный Python
- Проверьте, что PySide6 установлен: `python3 -c "import PySide6"`

### Проблема: Приложение не запускается на других Mac

**Типичные причины:**

1. **Архитектура процессора**  
   Сборка по умолчанию создаётся под архитектуру машины, на которой собирали:
   - Сборка на **Apple Silicon (M1/M2/M3)** → исполняемый файл **arm64** → не запустится на **Intel Mac**.
   - Сборка на **Intel Mac** → исполняемый файл **x86_64** → не запустится на **Apple Silicon**.  
   **Что делать:** собирать на том же типе Mac, на котором будут запускать. Либо собрать **universal2** (один .app для обеих архитектур) — см. раздел «Сборка universal2» ниже (требует Python и зависимости в формате universal2).

2. **Gatekeeper (разработчик не проверен)**  
   При первом запуске macOS может показать: «Dублёр не может быть открыт, так как разработчик не может быть проверен».  
   **Что делать:** правый клик по Dублёр.app → «Открыть» (или см. раздел «Проблема: macOS показывает предупреждение при первом запуске» ниже) и файл **dist/КАК_ЗАПУСТИТЬ_НА_ДРУГОМ_ПК.txt** (или **КАК_ЗАПУСТИТЬ_НА_ДРУГОМ_ПК.txt** в архиве для пользователей).

3. **Падение при запуске из терминала/IDE (SIGABRT, HIServices)**  
   На macOS 26 при запуске исполняемого файла напрямую (`.../Contents/MacOS/Dублёр`) из терминала или из Cursor/IDE приложение может падать с _RegisterApplication/abort.  
   **Что делать:** запускайте только через двойной клик по `.app` или командой `open "/path/to/Dублёр.app"`.

4. **Проверка архитектуры и логов**  
   На целевом Mac выполните в терминале:
   ```bash
   # Архитектура этого Mac
   uname -m
   # Запуск приложения (через open!)
   open "/path/to/Dублёр.app"
   ```
   Логи: `~/Library/Logs/Dubler/debug.log`. Если видите «Bad CPU type in executable» при попытке запуска — архитектура не совпадает (см. п. 1).

### Сборка universal2 (один .app для Intel и Apple Silicon) — опционально

По умолчанию сборка — **thin** (текущая архитектура), **psutil включён**. Для одного .app на Intel и Apple Silicon используется отдельный spec и скрипт.

**Шаг 1.1 — Python и виртуальное окружение**

1. Установите **Python 3.11 или 3.12 с [python.org](https://www.python.org/downloads/)** (пакет macOS «universal2» или «64-bit universal2»). Не используйте Homebrew — на Apple Silicon он ставит только arm64, из‑за чего PyInstaller выдаёт `IncompatibleBinaryArchError: ... is not a fat binary!`
2. **При ошибке SSL** (SSLError, OSStatus -26276) при установке зависимостей: один раз запустите «Install Certificates» из папки Python в /Applications: `open "/Applications/Python 3.12/Install Certificates.command"` — либо установите пакеты вручную с обходом проверки: `.venv_universal2/bin/pip install -r requirements.txt --trusted-host pypi.org --trusted-host files.pythonhosted.org`
3. Создайте отдельное окружение для universal2:
   ```bash
   ./scripts/prepare_universal2_venv.sh /путь/к/python3
   ```
   Пример: `./scripts/prepare_universal2_venv.sh /Library/Frameworks/Python.framework/Versions/3.12/bin/python3`  
   Будет создан каталог `.venv_universal2` и установлены зависимости из `requirements.txt`. При ошибке SSL скрипт повторяет установку с `--trusted-host`.

**Шаг 1.2 — Проверка архитектур (lipo)**

Перед сборкой проверьте, что ключевые бинарники — fat (x86_64 и arm64):

```bash
./scripts/check_universal2_lipo.sh
```

Скрипт выведет результат `lipo` для Python, stdlib и psutil. Если **psutil** окажется thin (одна архитектура), в текущем **Dублёр_universal2.spec** он уже в `excludes` — сборка пройдёт без psutil в бандле (в app.py он опционален). Если lipo показал для psutil fat — можно убрать psutil из `excludes` в `Dублёр_universal2.spec` и добавить `psutil` в `hiddenimports`.

**Шаг 2 — Запуск сборки universal2**

```bash
./build.sh
```

Скрипт использует `.venv_universal2/bin/python` и spec-файл **Dублёр_universal2.spec** (`target_arch='universal2'`). Результат: `dist/Dubler_VERSION_YYYY-MM-DD.dmg` — готовый DMG с universal2 приложением (x86_64 + arm64), установщиком и инструкцией.

**Проверка результата**

```bash
file "dist/Dублёр.app/Contents/MacOS/Dублёр"
lipo -info "dist/Dублёр.app/Contents/MacOS/Dублёр"
```

Ожидается упоминание обеих архитектур. Чеклист для теста в ВМ: `./run_vm_test_checklist.sh`.

**Примечание:** ijson в приложении использует только чистый Python-бэкенд; C/yajl-бэкенды в spec исключены. Подробности — в [PROJECT_LOG.md](PROJECT_LOG.md).

### Проблема: Приложение не запускается (общее)

**Решение:**
1. Запускайте только через `open "dist/Dублёр.app"` или двойной клик по `.app`. Не запускайте исполняемый файл `Contents/MacOS/Dублёр` напрямую (на macOS 26 это вызывает SIGABRT).
2. Проверьте логи: `~/Library/Logs/Dubler/debug.log` или Консоль (Console.app).
3. Убедитесь, что все зависимости установлены.

### Если приложение не запускается на другом Mac (диагностика)

Когда приложение не открывается ни двойным кликом, ни через `open`:

1. **Запуск из терминала** — чтобы увидеть ошибки импорта или другие сообщения:
   ```bash
   "/path/to/Dублёр.app/Contents/MacOS/Dублёр"
   ```
   или из папки, где лежит .app:
   ```bash
   "./Dублёр.app/Contents/MacOS/Dублёр"
   ```

2. **Крэш-отчёты:** `~/Library/Logs/DiagnosticReports/` — откройте последние файлы с именем процесса Dублёр или Python.

3. **Системные логи:** откройте **Консоль** (Console.app), введите в поиск имя приложения или «Dублёр» и посмотрите сообщения в момент запуска.

4. **Первый запуск после копирования с DMG:** в образе только приложение и папка «Программы». Если Mac блокирует приложение («разработчик не проверен», «приложение повреждено»), используйте правый клик по Dублёр.app → **«Открыть»** (см. раздел ниже).

### Проблема: macOS показывает предупреждение при первом запуске

**Решение:**
Если при первом запуске macOS показывает предупреждение "Dублёр не может быть открыт, так как разработчик не может быть проверен":

**Самый простой способ:** правый клик (или Control+клик) по Dублёр.app → **«Открыть»** → в диалоге нажмите «Открыть». После этого приложение можно запускать обычным двойным кликом.

**Альтернатива (через настройки):**
1. Откройте **Системные настройки** → **Безопасность и конфиденциальность**
2. В разделе "Общие" найдите сообщение о заблокированном приложении
3. Нажмите кнопку **"Открыть в любом случае"**
4. Подтвердите действие

После этого приложение будет запускаться без предупреждений.

## Подпись кода приложения

### Что такое подпись кода?

Подпись кода (code signing) - это процесс, который позволяет macOS идентифицировать разработчика приложения и обеспечивает целостность приложения.

### Типы подписи

**Ad-hoc подпись** (используется в проекте):
- ✅ Не требует Apple Developer аккаунта
- ✅ Работает для локального использования и распространения
- ✅ Автоматически выполняется скриптом сборки
- ⚠️ macOS может показывать предупреждение при первом запуске (решается через настройки безопасности)
- ❌ Не подходит для публикации в Mac App Store

**Официальная подпись** (для App Store):
- Требует платный Apple Developer аккаунт ($99/год)
- Необходима для публикации в Mac App Store
- Требует настройки сертификатов в Xcode

### Текущая конфигурация

Приложение использует **ad-hoc подпись**, которая:
- Настроена в файле `Dублёр.spec` (bundle identifier: `com.filmbackup.dubler`)
- Автоматически выполняется скриптом `build.sh` после сборки
- Использует команду `codesign -s -` для локальной подписи

### Ручная подпись (если необходимо)

Если нужно подписать приложение вручную:

```bash
codesign --force --deep --sign - "dist/Dублёр.app"
```

Проверка подписи:

```bash
codesign --verify --verbose "dist/Dублёр.app"
```

Чтобы раздавать приложение одним файлом (образ диска):

1. Соберите приложение (см. выше), затем:
   ```bash

   ```

   ```bash
   ./create_dmg.sh --build
   ```

2. Результат: **dist/Dubler.dmg** — сжатый образ с минимальным содержимым: только Dублёр.app и папка «Программы», крупные иконки в окне установщика.

3. Инструкция для пользователей: открыть DMG → перетащить Dублёр в папку «Программы».

## Примечание о подписи кода

При сборке приложения может появиться предупреждение о подписи кода. Это нормально и не критично для работы приложения. Скрипт `build.sh` автоматически выполняет ad-hoc подпись с hardened runtime после сборки, что устраняет большинство предупреждений и улучшает совместимость с macOS Gatekeeper.
