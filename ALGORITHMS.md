# Алгоритмы (Film_backup_pro / Dублёр)

Краткое описание алгоритмов, используемых в проекте.

| Алгоритм | Описание |
|----------|----------|
| **Единое сканирование источников** (`scan_sources_unified`) | Один проход по всем источникам (папки/файлы): собираются общий размер, список файлов с метаданными (source_path, destination_path, category, size, relative_path и т.д.) и размеры по каждому источнику. Поддержка отмены через `should_cancel`. |
| **Разрешение конфликта по пути** | При существовании файла в назначении показывается диалог «Файл уже существует»: Заменить / Пропустить / Оставить оба; опция «Применять ко всем». Решение хранится в `copy_conflict_policy` для последующих конфликтов. |
| **Sample-signature** (`compute_sample_signature`) | Сигнатура файла: blake2b(16) от конкатенации размера (8 байт LE), первого и последнего чанка. Для файлов < 2×chunk читается весь файл. Используется для быстрого отсева несовпадений без полного MD5. |
| **MD5 с адаптивным блоком** (`compute_md5`) | Вычисление MD5 по блокам; размер блока зависит от размера файла: 10 МБ (≤10 GB), 15 МБ (10–50 GB), 20 МБ (>50 GB). Учитывается `cancel_token`. |
| **Стратегия выбора метода копирования** (`get_copy_method`) | По размеру файла: < 100 МБ → `SHUTIL` (блок 1 МБ + MD5 по ходу), ≥ 100 МБ → `BLOCK` (адаптивный блок 10/15/20 МБ + MD5 по ходу). |
| **Адаптивное блочное копирование** | Копирование с прогрессом и паузой/отменой: для больших файлов блоки 10/15/20 МБ, хеш MD5 считается во время чтения, периодический вызов `progress_callback` (интервал ~0.1 с). |
| **Трёхфазная верификация (Level A/B/C)** | Проверка пары исход/назначение: A — сравнение размеров, B — сравнение sample_signature, C — сравнение полного MD5. При несовпадении на любом уровне верификация считается неуспешной. |
| **EMA скорости** (`SpeedCalculator`) | Экспоненциальное скользящее среднее для скорости копирования: `EMA_new = α × current + (1 − α) × EMA_old` (α по умолчанию 0.2). Нулевая скорость не обновляет EMA. Используется для стабильного ETA. |
| **Категоризация по расширению** (`get_file_category`) | Определение категории файла (Video / Audio / Photo) по спискам расширений (VIDEO_EXTENSIONS, AUDIO_EXTENSIONS, PHOTO_EXTENSIONS). По умолчанию — Video. |
| **Преобладающая категория папки** (`get_folder_predominant_category`) | Рекурсивный обход папки через `fs.walk`, подсчёт файлов по категориям (с учётом `is_system_file`), возврат категории с максимальным числом файлов. |
| **Повтор при временных ошибках** (`is_temporary_error` + `RetryHandler`) | Считаются временными: PermissionError и OSError с errno EAGAIN, EINTR, EBUSY. Повтор вызова с задержкой (по умолчанию 3 попытки, 1 с), логирование. |
| **Атомарная запись хранилища хешей** | Запись в `.tmp`, затем `replace(temp, target)`; при сжатии — gzip. Порог автосохранения по числу изменений и по таймеру. |
| **Батчинг обновлений прогресса** (`ProgressUpdateBatcher`) | Накопление обновлений прогресса из фонового потока и отправка в UI по таймеру (100–200 мс) через Qt-сигнал, чтобы не перегружать главный поток. |
| **Этапы бэкапа (Strategy)** | Последовательность этапов: InitializationStage (sleep prevention, сканирование объёма, инициализация проекта) → CopyingStage → VerificationStage → FinalizationStage (логи, уведомления, callback). |
